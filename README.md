# Star Control 3 – Spanish translation toolkit

```
ORIGINAL/   untouched game files (READ-ONLY, never modified by any tool)
ASSETS/     everything translatable, extracted from ORIGINAL (edit these)
SC3E/       the Spanish game, generated by tools/build.py (do not edit by hand)
tools/      extractor, builder and the reverse-engineered codecs (Python 3 + Pillow, capstone only for analysis)
```

## Workflow

Shortcut: **extract.bat** (ORIGINAL -> ASSETS, asks before overwriting) and **inject.bat** (ORIGINAL + ASSETS -> SC3E, optional steps argument, e.g. `inject.bat text,exe`).

```
python tools/extract.py            # ORIGINAL -> ASSETS  (text fonts pics voices; already done once)
   ... edit files in ASSETS ...
python tools/build.py              # ORIGINAL + ASSETS -> SC3E  (full copy, then overlay edited assets)
python tools/build.py --no-copy --only text,exe      # quick re-run of selected steps on the existing SC3E
```
Unchanged assets are carried over byte-for-byte from ORIGINAL; only edited ones are re-encoded.
Run the game from `SC3E` with DOSBox / DOSBox-X (`mount c SC3E`, `sc3.exe`).

## What is in ASSETS

| Path | Content | How to edit | Back into the game |
|---|---|---|---|
| `text/SC3STR.txt` | all 6249 dialogue/story strings, one per line `id|text` | translate the text after the bar, keep ids and line count | `SC3STR.DAT` rebuilt (new Huffman tree) |
| `text/SC3EXE.txt` | 1744 UI/help/menu strings of `SC3.EXE`, `offset|text` | translate; keep `%s %d` codes in the same order | strings are relocated to a new data object of the EXE, any length |
| `text/SC3EXE.technical.txt` | file names, debug formats | do **not** translate (ignored by the build) | – |
| `text/ref/*.en.txt` | pristine English copies | reference only; the build diffs against them | – |
| `graphics/pic/STARnnn/EEE.png` + `pic.json` | all 60 280 picture entries of the 170 `.PIC` files (indexed PNG) | edit pixels keeping the palette (non-indexed PNGs are re-quantised to the entry palette); size may change | `.PIC` rebuilt (edited entries stored uncompressed) |
| `graphics/fonts/STARnnn.png` + `.json` | the 6 bitmap fonts, extended to codes 0x80-0xFF with Spanish glyphs | redraw glyphs (cell = bytes-per-row*8 x height), change advance widths in the json | `.FNT` rebuilt |
| `voices/Vnnnn.wav` + `voices.json` | 3592 voice samples (8/16-bit mono PCM, 22050 Hz) | replace the wav with a new recording (mono, 8 or 16-bit PCM, any rate) | `STAR001.VOC` rebuilt (replaced entries stored as raw PCM) |
| `graphics/palettes/*.png` | swatches of the 49 distinct palettes found in the game (Q files and STAR000.PIC) | – | – |
| `charmap.json` | Unicode -> game byte (Latin-1 codes) for `á é í ó ú ñ ü Á É Í Ó Ú Ñ Ü ¿ ¡` | – | used by text builds |

Text escapes in the `.txt` files: `\n` newline, `\t` tab, `\\` backslash, `\s` a protected leading/trailing space, `\xNN` raw byte.
`tools/build.py` warns when a translation changes the printf codes (`%s`, `%d`...) of a string.

### About picture colours
Only `STAR000.PIC` stores palettes; the other 169 PIC files contain **indices only** and the game applies palettes from code at run time.
The PNGs therefore use the standard game palette (`PIC000#3`, in blue = transparent key) as *preview* palette: ships, planets and
sprites look right, some backgrounds (e.g. starfields) may show other colours in the game. The palette never changes pixel indices, so editing is safe.
Palette blocks can be partial (`STAR800`, `STAR600`): they overwrite only a range of colours. In files that contain partial blocks, partial blocks accumulate over the default palette and stay in force, while full 768-byte blocks are alternative palettes that apply to their own entry only (so e.g. the cursor icons keep the system colours 254/255).
Rule used: 400-699 planets/UI = `PIC401#0`, 700-703 colony sprites = `PIC715#21`, files with their own palettes use them, everything else = `PIC000#3`.
`python tools/setpal.py list|swatches|<STARnnn> <palette>|all [auto|<palette>]` recolors previews with any palette found in the game.

## Reverse-engineered formats (details in `tools/*.py`)

* **SC3STR.DAT** – per-string Huffman (bits LSB-first), tree = i16 pairs (leaf = -(byte+1)), 0 = end, 0x1A+n = dictionary word. `tools/sc3str.py`
* **\*.PIC** – 20-byte entry table, optional 6-bit VGA palette, pixel data raw or LHA lh4 (4 KB window). `tools/picfile.py`, `tools/lha.py`
* **STAR001.VOC** – offset table (3879 slots, 4 KB aligned); entry = type, size, 44-byte WAV header, payload; type 0x20 = block ADPCM (`tools/sc3voc.py`), type 0 = raw PCM. `tools/vocfile.py`
* **\*.FNT** – 10-byte header, width table (last+1 bytes), 1-bit glyphs. The engine supports `last = 0xFF` natively. `tools/fntfile.py`, `tools/fonttool.py`
* **SC3.EXE** – DOS/4G LE executable. `tools/lepatch.py` adds a new data object and re-targets the fixups of changed strings (no in-place length limit). `tools/leimg.py`, `lefix.py`, `x86.py` are analysis helpers.

## Not done / limitations

* **`.Q` files (519 animation/video files)** are copied unmodified. Structure known: 26-byte header (magic 0x6839, size, frame count), then chunks `{u16 type, u32 size}` (1 = palette, 5 = 256 x u16 mask table, 9/2/11 = frame data, 0xFFFF = end). The pixel codec is not decoded; they are not expected to contain text.
* `STARCON3.001`, `RESTART.DAT` and the sound drivers (`*.DIG`, `*.MDI`, `GM.XMI`) are copied unmodified.
* Edited pictures/voices are stored uncompressed, so `SC3E` grows with the amount of edited graphics/audio.
* Long translated strings are fine for the engine's text boxes (they word-wrap), but strings that the game formats into fixed buffers with `sprintf` could overflow if made much longer; keep an eye on very long UI strings.
* Accented glyphs were composed automatically from the base letters; refine them in `graphics/fonts/*.png` if desired (the 6-row font `STAR002` has no room for marks and uses the plain letter).
* `SC3E` contains copyrighted game data: distribute the tools/ASSETS text, not the generated directory.
